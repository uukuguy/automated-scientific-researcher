# ASR 如何做研究：已经做成什么，今后怎样协作

更新：2026 年 11 月 4 日。

这份说明先解释单研究员项目做成了什么、ASR怎样自动开展研究，再介绍多研究员协作、接续研究和人类评价器。

先交代目前的位置：**单研究员已完成过有独立检验的模拟项目。组织者和两位负责人随后完成了一次真实的补样比较，现在正接着处理新的研究要求。新团队结果的独立验证、多个方向同时运行，以及长时间运行中完全自动恢复和收尾，仍未完成。**

## 一、先前单研究员项目做成了什么？

### 给它一个真实可做的模拟项目

我们模拟了一位人类研究员的处境：手里有一个电网预测模型，在熟悉的样本上表现很好，但碰到某类训练时没见过的样本，误差明显增大。

这里的“陌生样本”，就是 OOD 样本：它们与原来的训练分布不同。比如，某些区域的用电负荷组合超出了模型以往学习的范围。“陌生”不一定意味着异常或不合理，只是模型没有充分学过。

交给 ASR 的问题是：

> 能否生成一批有帮助的新训练样本，让这个模型在这类陌生场景上表现更好，同时不要让原来的能力退化得太严重？

我们准备了目标模型、原始数据、表现不好的样本和验收标准。具体怎样诊断、怎样补数据、怎样安排对照实验，由 ASR 的研究员自己决定。

这个项目使用合成电网场景，但计算、训练和测试都实际运行了。“模拟”指的是客户项目和数据场景，不是让 AI 编造实验结果。

### 它自己提出方案，并真正做了比较

研究员提出了不同的补数据思路：针对薄弱区域补样本、在较大范围内补样本，以及只在原来的熟悉区域补样本。

它随后编写采样与分析代码，生成了 **704 条新样本**，训练并比较了 **9 个增强模型**。其中，576 条样本用于不同方案的训练，128 条用于开发阶段的检查；并不是把全部 704 条数据塞进同一个模型。

最后选中的模型使用原来的 128 条训练样本，加上新生成的 64 条样本，共 192 条。模型本身的结构和训练规则没有改变，这样才能判断收益是否来自新增数据。

### 先交卷，再看考试答案

研究员必须先选定模型，并写清楚预期结果。之后，独立评价器才使用它此前没见过的测试数据评分。

这样可以避免一种常见问题：研究员反复看测试结果，再不断修改方案，最后把“针对考题练熟了”误认为泛化能力提升。

结果是：

| 检查内容 | 实际结果 | 应当怎样理解 |
|---|---|---|
| 陌生场景上的预测误差 | 下降约 **83%** | 在这类场景上，补数据确实有帮助 |
| 熟悉场景上的预测误差 | 约增至原来的 **11 倍** | 原有能力有退化，不能只报好消息 |
| 是否满足事先约定的要求 | 满足 | 原先误差很小，增大后仍在固定的绝对误差容许范围内 |
| 相同训练材料能否再次得到相同模型 | 可以 | 结果能够复现，不只是一次偶然运行 |

所以，具体交付是：**一批能帮助这个模型的新训练数据、一个改善后的模型，以及可复查的实验和研究报告。**

### 这件事证明了什么，还没证明什么？

它证明了 ASR 已经能够接收一个问题，自主提出方案、做真实实验，并得到经独立测试支持的结果。

它还没有证明这套方案适用于真实电网业务，也没有证明它是一个新算法。我们也尚未通过充分的拆分实验，弄清楚方案里每个组成部分分别起了多大作用。

此外，样本满足电网方程，并不意味着它们适合实际运行。这批场景仍有运行约束越限，一些线路限额也未能评估，不能作为安全运行建议。

自动化也还不完整：研究过程中遇到工具和上下文问题，需要开发侧协助恢复。最终报告确实由 AAR 研究员写出，但最后达到时间上限，归档由控制侧完成。这些介入和失败记录都保留了，没有算成“全程无人照看”。

## 二、ASR 是怎样实现自动研究的？

可以把它理解成：**一个会持续思考的研究员，配上能做实验的工具、不会随聊天消失的研究记录，以及独立的检查机制。**

### 研究员决定下一步，系统执行真实工作

当前实际运行的是 AAR 的研究循环，底层通过 pi 使用 Codex 订阅模型。

这些名字分别代表不同的事情：AAR 承载研究过程；pi 是运行模型会话和工具的程序；Codex 模型负责理解、推理和生成代码。外围的 ASR 系统负责实验准入、计算执行、证据和预算。

研究员的工作循环是：

> 查看问题和已有证据 → 提出下一步想法 → 写代码或调用工具 → 获得真实结果 → 分析结果 → 决定继续、修改还是停止。

下一步并非全部提前写好。例如，它可以发现某个方案改善了陌生场景，却损害了原来的能力，于是保留失败记录，转而比较其他方案。

自主性来自它根据证据作决定；可靠性则需要系统约束。不能因为 AI 说“实验成功”，就直接认为成功。

### 实验不是发生在聊天里

研究员通过工具提交具体请求，例如：“给这些场景求解可信标签”“用这批数据训练模型”“运行这段分析代码”。

ASR 先检查权限和预算，再在受控的计算环境中执行。完成后，将实际输出交给研究员，并保存本次使用的代码、数据、环境及运行记录。

如果程序报错，就记录执行失败；如果程序正常运行，但效果没有改善，就记录实验不支持预期。二者不能混为一谈，更不能通过不停改代码，把失败假说重新包装成成功。

### 研究历史保存在系统里，而不是只放在对话里

聊天会变长，模型可能忘记前面的内容，运行时也可能重启。因此，ASR 要分别保存：研究目标、假说及其修改、实验设计、每次执行、原始证据、候选发现和独立检查结果。

这样，即使换一个会话继续，仍然能知道“当时提出了什么”“在看见结果前决定了什么”“哪些结果反驳了原来的想法”。不过，怎样自动把这些记录整理成新会话所需的上下文，目前仍有待完善。

### 研究员不能自行给自己验收

正式评价由独立评价器完成。它依据冻结的材料重新计算，不直接相信研究员写在报告里的指标。

研究员也不能自行扩大预算、放宽验收要求，或者提前打开隐藏测试数据。预算和权限由控制层执行，人类仍然可以指导、暂停或停止研究。

目前各部分的职责是：

| 部分 | 用人话说，它负责什么 |
|---|---|
| AI 研究员 | 想问题、提假说、设计实验、写代码、解释结果 |
| ASR 控制层 | 守住目标、权限和预算，记录正式决定 |
| 实验执行层 | 真正运行计算，保存成功与失败的证据 |
| 独立评价器 | 重新检查结果是否支持结论 |
| 持久化研究记录 | 让研究历史不随对话结束或程序重启而丢失 |

## 三、多个研究员怎样一起完成这个过程？

规划中的变化是：现在由一个研究员承担的工作，将由研究组织者、多个方向负责人和具体任务执行者共同完成。

**当前这个单研究员，就是未来“方向负责人”的前身。** 它会保留自主思考和推进研究的能力，同时把部分具体工作交给 workers。

### 研究组织者：面对人，协调整个项目

研究组织者是架构里所说的 Super Agent。人类主要通过 Capstone 工作台与它交流。

它需要理解用户真正想解决的问题，整理已有材料和限制，提出研究方向的划分，协调优先级，并向人解释进展、分歧和取舍。它不逐步指挥每个负责人做每个实验，也不替独立评价器宣布结论通过。

例如，它会发现两个方向都在重复检查同一问题，或者发现两个方向的结论互相矛盾，进而组织合并工作或安排交叉检查。涉及扩大目标、增加预算或改变正式规则时，仍要经过授权。

### 方向负责人：负责一条方向的科学判断

每位方向负责人都有自己的研究循环，能够提出假说、安排实验、质询结果、修改方案，并建议继续或终止方向。

以同一个 OOD 项目为例，可能形成以下分工：

| 方向 | 要回答的问题 | 可交给 workers 的工作 |
|---|---|---|
| 失败原因 | 为什么模型在这些样本上表现不好？ | 检查标签、分析误差、研究训练数据覆盖情况 |
| 样本生成 | 怎样生成更有训练价值的数据？ | 实现生成器、检查重复样本、运行生成实验 |
| 训练与泛化 | 新数据是否有用，有什么副作用？ | 执行训练、做对照与消融、检查原分布退化 |

这是帮助理解的例子，不是每个项目都必须设置三个方向。方向可以来自组织者的初步拆解、人类的建议，或负责人在实验中发现的新问题；可以随证据合并或调整。

### 执行成员：完成明确的具体任务

worker 可以负责检索资料、实现某个方法、排查程序错误、运行一组实验或审查代码。它可以在任务内部自主推理，但需要清楚任务目标、允许的改动、资源额度和应交付的证据。

它返回的应该是代码、实验结果和依据，而不只是一句“完成了”。方向负责人负责判断这些产物对研究意味着什么。

每项任务必须有明确的唯一负责人，避免几个智能体同时修改同一实验，或重复消耗预算。

### 负责人之间可以直接讨论和评审

协作并不是所有消息都先交给组织者转发。

例如，失败诊断方向发现误差集中在某类负荷组合，可以直接把证据交给样本生成方向。训练方向发现生成方案带来严重的原分布退化，也可以直接提出反证，要求进一步检查。

讨论应当引用具体假说、实验和证据。不同负责人即使达成一致，也不能代替独立验收。代码审查 worker 与正式科学评价器，同样是不同角色。

### 图中的“双层样本生成架构”由谁设计？

“可行域发现与主动采样＋困难样本求解”是人类提供的候选方案，目前既不是ASR写死的系统结构，也不是P4研究员已经自主设计并验证的成果。P4没有实现持续学习边界和针对失败场景改变求解策略的完整循环。

未来团队应能自行构建这样的项目系统，也能提出更简单或不同的结构。如果从这张图出发，就要如实记录人类提供了架构建议；若只给问题，由团队提出结构，才属于自主架构设计。团队需要用实验判断第二层是否必要，不能为了符合图示而强行实现。

两层也不必对应两个负责人。方向划分由组织者和负责人根据问题讨论形成，方法的层次与人员的分工是两件事。可变的是研究方法、生成器和反馈策略；不可自行放宽的是权限、预算和正式评价规则。

### 一个项目从头到尾会怎样走？

1. 人类与研究组织者确认问题、材料、边界和预算。
2. 组织者提出方向划分，由各方向负责人自主推进。
3. 负责人安排 workers 做具体工作，实验仍通过统一控制层执行。
4. 各方向共享发现、交叉评审，保留分歧和失败证据。
5. 组织者向人汇报整体进展，协调需要进一步研究的问题。
6. 准备形成正式结论时，冻结方法与评价方案，交给独立评价器。
7. 研究团队解释结果，交付数据、代码、模型和有证据支持的结论；负面结论也可以成为有效交付。

### 如何避免变成一群 AI 互相聊天？

首先，按实际问题分工，每项任务要有明确产物和证据。其次，限制同时工作的数量和讨论规模，避免所有消息默认广播给所有人。最后，用统一账本管理预算与执行，不让每个角色各自建立一套调度系统。

AAR 将继续提供研究循环、共享发现、讨论和快照等协作基础；ASR 在此基础上补充角色、任务、权限、预算和独立评价机制；Capstone 负责人与研究组织的交互。

不同角色可以配置不同的模型运行时、技能和工具，但不会按模型厂商永久固定职位。需要审查代码的 worker 与负责项目交流的组织者，工具权限也不应该完全相同。运行方式继续遵循订阅优先，不在故障时偷偷转成付费 API。

当前配置允许一个组织者、最多两个方向负责人、两个执行成员和一个运行中的实验。已经验证了组织者与两位负责人轮流开展真实研究；同时开展多个方向的能力还没有验证。两个负责人名额不等于两个预设方向：组织者可以先安排一个方向做诊断，再依据证据增加、合并或调整方向；更多方向也可以排队推进。

扩展是否值得，要看同样预算下能否更快发现错误、更充分检验假说、得到更可靠的结论，而不是看启动了多少个智能体。

## 四、一轮结束后怎么继续，如何使用人类评价器？

研究组织交付一次结果后，人可以继续提出要求。例如：“请说明训练时到底用了哪些数据，
换一位成员能否得到同样结果，再用团队没见过的新样本检查效果。”组织者应接着已有
历史安排工作，负责人自己确定检查方法和分工，不能每次都像一个全新的项目从头开始。

这次已把这些要求交回原组织。团队承认外部归档已经完成，保留旧结果，另提出核对
材料和重新训练的工作安排。后续会把真实的外部检查结果再送回来，看他们如何解释
不一致、修订结论、继续研究。眼下已经看到接续安排，完整的外部结果反馈过程尚未验证。

人类还可以提供一套检查程序或服务，也就是“评价器”。研究团队交上候选方法或结果，
评价器返回哪些要求满足了、哪些没有满足、误差多大、哪里出了问题。团队可以看反馈
继续改进，但不能修改评价器、删除不利结果，或者把评价器没有做过的检查说成通过。
目前还没有接入人类提供的黑箱评价服务，组织已经提出所需接口和记录要求。

反复使用的反馈检查与最后验收要分开。前者帮助做研究；后者在候选方案确定之后，
使用没有参与反馈的新数据，由独立服务执行。即便评价器不公开代码和样本，只要反复
告诉团队分数，也可能让团队逐渐迎合这批测试。因此，曾经用于反馈的测试不能再被
称作下一轮“完全没见过”的验收数据。以后的新候选也要保留版本，旧结果不能改掉。

所有给人看的报告、说明和评价请求用中文，先说结果、问题和需要的支持。每次讨论、
调用、失败和修改都有记录。原始英文材料和机器数据保留用于查证，中文阅读版本说明
对应的原稿，避免翻译和整理改变研究事实。
