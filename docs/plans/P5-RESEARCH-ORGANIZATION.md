## 研究任务与自主边界

任务是针对目标模型的OOD弱点，构建有训练价值的样本生成方案，独立检验收益、成本和原分布退化。P4材料与全部成功/失败证据可作为已知起点，不把P4隐藏测试结果继续当作新的盲测证据。新确认实验需重新冻结评价方案和独立测试材料。

研究组织者读取项目材料，自主提出方向划分；方向负责人可质疑划分、提出新方向或调整建议。开发侧只实现角色、能力和资源边界，不预设“采样负责人”“求解负责人”等固定科学职位，也不要求必须同时启用所有名额。

图中的双层结构是人类提供的候选方案，必须保留来源。团队可实现、修改或拒绝它；两层不对应固定岗位。P4全部新增标签求解成功，不能据此声称已经发现需要特殊求解策略的困难样本。方程可解、运行可行、特定算法收敛与训练价值必须分别判断。

## 最小组织与资源约束

建议起点：组织者1个、活跃负责人最多2个、共享worker并发最多2个、实验并发最多1个。这些是待校准的容量建议，不是已授权模型预算或永久部署配置。允许单方向起步、多方向排队。

方向创建、拆分、合并、终止或移交均记录依据、证据引用、唯一任务负责人和资源影响。组织者在已授权范围内协调；改变总预算、权限或正式评价条件须取得相应授权。停止、恢复和并发约束由同一Control账本执行，不建立第二个调度权威。

角色职责与runtime绑定分离，优先复用已验收订阅能力；不同角色分别配置工具权限。不能把单轮对话成功当成完整研究运行时集成。订阅运行禁止注入API密钥或自动转为付费API。

## 推进顺序

1. 映射现有AAR循环、论坛、快照和Control身份，确定可复用部分与最小缺口；形成可执行实现任务与检查点。
2. 实现角色身份、方向/任务版本、唯一归属、定向通信与负责人自主循环。先验证单一项目中的协作、停止和恢复，再扩展规模。
3. 允许团队通过受控项目代码实现生成器、主动采样和候选困难求解策略；冻结代码、输入、依赖和输出。研究代码不能改评价器或读取隐藏材料。
4. 补齐P4暴露的上下文恢复和报告发布预留；明确超限记录及可恢复处理，不能靠静默重试或自动加预算。
5. 在记录有限预算后实际运行组织者分解问题、负责人质询、worker实现与实验、跨方向讨论和证据综合。任何开发侧介入均记录，不能冒称团队自主完成。
6. 冻结候选与独立评价协议，检验科学结果及相近预算下的协作收益，交付项目代码、样本、模型、报告及完整失败记录。

## 验收要点

| 要点 | 所需证据 |
|---|---|
| 自主形成研究方向 | 实际模型阅读委托后提出方向及理由；启动配置没有写死科学主题。允许合理选择一个方向 |
| 可调整组织 | 实际任务移交/调整记录；若没有调整必要，不要求制造科学转向，机制另以工程测试验证 |
| 自主构建方法 | 团队产出的可执行项目代码、版本、实验与替代方案；区分人类建议和团队贡献 |
| 有效协作 | 定向讨论和交叉评审引用证据；独立任务归属、预算与停止/恢复生效 |
| 科学可信性 | 对照、必要消融、原分布退化、物理/运行有效性分开报告；冻结后独立检验，保留负面结果 |
| 组织是否值得 | 在可比较的任务与预算下评价结论质量、错误发现与协调成本，不预设多智能体必然优于单研究员 |
| 人类交互 | 组织者输出可追踪的解释与控制请求；Capstone实际联调须单独验证，本仓库文档不替代交付回执 |

实现图示结构本身、增加agent数量或得到漂亮训练指标，都不能单独关闭P5。否定双层架构或未发现改进也可以形成有效科学结论，但必须另行如实说明组织能力和自主执行是否达到验收要求。

## 第一实现切片：组织记录与任务归属（2026-11-03）

沿用已批准职责，直接在Control的SQLite事务中追加版本化组织记录，不增加调度器。记录类型为policy、member、direction、task、message。人类凭据设置容量和角色成员；组织者决定方向，负责人可提出方向建议和给自己方向安排任务；执行者只能领取及交付分配给自己的任务。正在执行的任务不能直接换人或改题，必须先由执行者完成/确认取消，后续再创建明确任务。终止方向前须处理未完成任务。

`asr_service/organization.py`负责校验、版本、授权、容量和可分页读取；`ControlService.change_organization(token,project,run,*,kind,entity_id,expected_revision,idempotency_key,document)`与`organization_records(token,project,run,*,after=0,limit=100)`是内部接口。HTTP入口为GET/POST `/v1/projects/{project}/runs/{run}/organization`。记录身份来自认证主体，不允许请求伪装角色。方向主题是自由文本，不带预置科学类别。

## 第二实现切片：角色绑定到已有运行预留

已实现`asr_service/organization_runtime.py`与现有`claim_runtime`/`run_session`的连接。启用组织策略的研究运行必须提供经过核对的成员角色、修订、成员记录摘要和工具配置摘要，才能预留模型时间；非组织运行保持原接口与历史幂等身份。策略不能覆盖尚未退出的旧会话，绑定的成员在退出前不能修改身份。每个项目/运行/成员/角色使用独立的pi配置与对话目录，仍共享原Control预算和已用成本。

工程验证包含过期身份、未批准工具profile、重复预留、运行中改角色、旧进程未对账、新角色继续计费，以及无模型调用的启动失败恢复。单run单活跃runtime保护仍保留；此切片是轮流执行角色的连接基础，不是并行模型验收。各角色独立模型策略、任务到真实实验的权限绑定、AAR组织者决定接续工作和实际多角色科学循环仍待实现。
