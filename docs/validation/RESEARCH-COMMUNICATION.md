# 研究交流记录

用户要求：**整个研究过程的交流过程都要记录完整。**

研究原始记录保存在每次运行目录中，交流档案是带来源索引的独立副本。
保留角色实际收到和发出的可见消息、跨角色讨论、工具请求与返回、任务及契约版本、
人类指导与控制回执、失败和恢复记录。最终报告不能代替这些原文。

当前组织入口会保存完整启动提示与项目说明；运行事件逐条写入序号、UTC 收集时间，
flush/fsync 后继续。结束或失败时导出档案并在运行报告中记录索引哈希。
归档错误明确报告，恢复归档不应重跑科研计算。

已有运行可单独归档：

```sh
uv run python -m integrations.runtimes.communication_archive \
  --root artifacts/<run> --output artifacts/<new-communication-archive>
```

目的目录必须不存在。`manifest.json` 列出来源哈希、角色会话与原生日志关联、缺口和
脱敏位置；`inventory.json` 校验导出文件。多个角色会话可以关联同一个持续增长的
原生日志，不能因此把它们当作重复会话删除。每个快照保留自己的时间点。

进行中的会话、缺失原文和不完整 JSONL 行会明确列为缺口。历史消息时间只能使用
原记录，不事后推造。工具若原本返回摘要、分页或截断文本，档案保留实际返回内容，
不声称这等同于工具访问文件的全部内容；科学材料继续由原始证据仓库保存。

凭据、私有思考内容和签名不进入可见交流导出，原生日志仍留在受限目录。
既有 runtime 未保存原始 provider stderr，不能追补；外部开发聊天也不会自动变成
研究团队的原始会话。用户新要求已用原文记录并发布为项目指导。
