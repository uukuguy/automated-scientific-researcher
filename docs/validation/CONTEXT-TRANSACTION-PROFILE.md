# 上下文准备事务的本机测量

先用隔离临时数据库测量，再拆出已验证会话的重复材料重建。优化后仍在提交时重读冻结来源、比较原生观察并检查文件版本；原件和数据库来源发生变化时拒绝旧结果。没有模型请求、科研执行或历史研究库修改。

每组3次独立准备请求，另跑一次函数剖析。计时从`BEGIN IMMEDIATE`取得写锁后开始，至连接上下文退出结束，包含提交和连接关闭，是事务包围区间的保守测量，不是精确底层锁持有时长；不包含等待锁时间。SDK投影耗时包含在另存的请求总耗时中，不包含在本表内。

1MiB消息的修改前单次剖析中，`conversation.materials`累计约12.5ms，约占准备函数24.2ms的一半。修改后材料重建移出写事务；准备函数剖析约12.1ms，剩余主要为JSON序列化、状态指纹与数据库提交/关闭。剖析开销不混入上表计时样本。

这是本机合成单消息负载，不覆盖真实复杂交互、大量小消息、并发竞争、冷缓存、生产尾延迟或任意规模。3次样本不能形成性能服务保证，也不能据此设定新的超时或容量上限。暂不继续扩大事务改造；剩余成本需要真实负载依据，附件全量内存与崩溃对账仍开放。

复现命令：`uv run python scripts/context_transaction_probe.py --output <新的结果文件> --repeats 3`。脚本使用现有测试夹具、临时库和固定pi SDK。修改前基线为`5b11e81`；本次代码、脚本和原始测量指纹在`CONTEXT-TRANSACTION-PROFILE.json`，原始文件保存在`artifacts/context-transaction-profile-001/`。不要覆写已有测量文件。

新增3项工程检查：重建时另一SQLite连接可写；重建期间原件改写拒绝；重建后数据库来源变化拒绝。完整回归结果见同名JSON验收记录，不以性能测量替代正确性检查。
