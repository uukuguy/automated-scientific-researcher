# P5：团队坐标接入正式实验协议

团队交付的768个不同坐标现已转换为Control支持的配对协议：8个种子、每个4组，
共32个64槽位求解批次，合计2048个拟议求解槽位。转换不改变任何坐标或分组，
不重跑生成器，不补样，也不消耗模型或数值实验预算。

## 独立检查做了什么

`research_projects/paired_acquisition/generator_admission.py`从Control读取真实完成的
analysis证据，核对manifest、执行请求、源代码和外部固定candidate hash，再检查：

- 固定种子及每种随机流编号、块名和块数量；
- 四组固定顺序、展开坐标和共享块逐项对应；
- 公共输入坐标hash、六位精度、范围与公开坐标舍入碰撞；
- 不同块/种子不得重复，原生配对协议结构与槽位计数有效。

它使用冻结提案的字面规则，不导入生成器的ARMS，也不相信其accepted字段。
这是一层独立的结构检查，不是重新实现随机生成算法、验证全部随机数来源，
也不是独立的电气或泛化评价。原始源码和已发现的自检漏洞原样保留。

## 用真实失败反例验证

评审trial保留了错误顺序、错误产物hash和“原自检通过”的记录，没有保存错误产物
全量正文。因此从原始完整candidate只重建TT的那项顺序变更，并确认所得hash与
真实评审记录完全一致。新的独立检查拒绝它：`literal arm order mismatch`。
不是任意构造一个不同错误后声称复现；也没有修改旧的实验输出。

候选原hash：f28262870d046f46d3c22c61e06df639b789966ee459c9d4723348bd3bad0176。
原生协议hash：f2a1709a72ce0149b8161fd6a9b8243031f4b89d1f4c1150c5ee732fb5045516。
原生协议绑定原candidate hash；两者格式不同，hash不同是预期结果。

## 接续验证与范围

所有32个arm都经现有training_adapter.prepare准备固定IEEE118输入和来源hash，
共2048槽位。每个arm仍为64标签槽位，对应原始128训练行加本arm有效标签；
没有把不同实验组的标签混在一起。这里尚未产生标签，不能称为192行训练已完成。

独立临时Control夹具验证了完整协议准入：预算不足明确拒绝；足够的测试配额下，
实际团队坐标可进入现有标签准备事务，保存64个预期输入和原始顺序；随后取消
未执行任务，预留归零。没有启动容器、求解或拟合。源团队研究的预算和trial完全不变。
已有真实容器标签/训练适配验收仍见P5-STUDY-ADAPTER-FLOW.md，不冒充本轮新计算。

归档artifacts/p5-generator-admission-001含完整协议/来源绑定、全部arm准备摘要、
第一arm完整准备材料、真实负例重建核对结果、报告及文件清单。
机器可核对摘要见P5-GENERATOR-ADMISSION.json。

这份协议只覆盖原方案中的2048增强槽位。完整3584槽位还包括1536个新评价面板槽位，
以及33次fit、冻结选优、复现和独立开发/最终评分；这些没有由转换自动获得授权或执行。
下一步是完整研究契约与新评价面板接续，而不是重新打开旧分析运行追加标签。

验证：9项专项测试通过；完整回归399项，374通过、25环境跳过。日志/tmp/asr-generator-admission-full.log；归档清单及适配器源码hash已复核。
