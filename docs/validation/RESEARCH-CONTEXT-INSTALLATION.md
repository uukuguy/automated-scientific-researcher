# 研究上下文压缩、安装与继续执行：闭环验收

2026-11-04。本轮完成了指定触发的实际闭环：生成摘要 → 另一会话复核 → 冻结安装内容 → pi原生写入 → Control重新读取核验 → 同一研究会话继续调用模型 → 按来源编号找回旧原文。

这次是上下文工程验收，没有开展新的电网实验，也不增加任何科学结论。人类可查看的结论和限制如下；详细核查项见[机器回执](RESEARCH-CONTEXT-INSTALLATION.json)。

## 实际做到了什么

使用本机pi 1.5.0与openai-codex订阅，模型为gpt-6.1-sol。材料来自此前团队冻结的真实研究报告，保留内部复现、原分布退化、未完成独立评价等限制。摘要生成与复核使用不同成员、不同会话；它们使用同一模型，不是独立科学评价。

同一目标会话实际安装了三次自定义摘要。最后一次，SDK可见文本由36,595个UTF-8字节降至18,681字节，约减少49%。这是文本字节量，不是提供方token计数或费用降幅。安装后模型再次回答七项事实，全部与冻结标注一致。随后它实际调用原文回查工具，找回最早报告并给出两段逐字正确的引文。

| 实际安装 | 安装前/后可见字节 | 结果 |
| --- | ---: | --- |
| installation-001 | 26,153 → 38,331 | 原生写入与继续执行成功；原型有系统说明重复，未透传stdout诊断，不能当最终效率或回执链验收。 |
| installation-003 | 39,208 → 35,718 | 正式RPC通知到达宿主，核验回执先于下一次模型请求；七项事实通过。 |
| installation-005 | 36,595 → 18,681 | 原生系统说明逐字重放后去重；完整核验、继续执行及七项事实通过。随后原文回查也通过。 |

核查的不只是“写出一条摘要”：实际压缩条目的父节点、切点、摘要、票据和fromHook标记都与授权一致；原日志的既有字节前缀未改变；被摘要的记录从SDK投影中退出，保留尾部仍存在；需要重放的材料逐字对应。最后两次安装均确认先收到核验回执，再发送继续请求。

## 为什么不会把记录悄悄丢掉

核心算法不导入pi。它复算来源指纹、摘要和复核绑定，按完整工具交互组选择替换范围。需要移出的保护项进入逐字重放材料；原生SDK已经重放的当前系统说明单独逐字核对，避免再复制一遍。摘要正文不由安装器改写。

Control只接受宿主准备的安装请求，在同步回调里重新核对当前成员、运行所有权、进程出生身份、会话文件、分支、研究状态和来源。安装票据限当前边界使用一次。pi写入以后，Control再次读取文件和实际SDK投影；未核验成功时，宿主禁止继续模型请求，保留原任务、票据、失败和原日志，要求明确恢复。

旧原文通过`asr.research_note conversation_read`读取本人冻结的可见记录，按Unicode字符分页并返回完整来源哈希。它不暴露私有思考、任意本机路径或其他成员记录；历史内容不自动成为当前指令或实验权限。

## 保留下来的失败与修正

- 恢复运行改变控制版本后，旧笔记被拒绝。重新采用当前版本的笔记，复用了两次已经完成的会话，没有重复模型调用。
- 第二轮复核会话接受摘要，但引文检查拒绝了JSON转义后的中文。新增明确的已安装记忆`summary`解码视图，仍要求连续原文逐字匹配；没有修改模型原答或把否决改成接受，之后另起了新的摘要与复核。
- 一次来源登记在模型调用前被拒绝。原因是辅助进程把跨管道块的UTF-8中文解码成替换字符；拆开中文字节的测试复现了问题，修复流式解码后重新登记。
- 早期系统说明被重复放入摘要，反而扩大了上下文；现改为核对SDK原生重放。首次交流导出的目录筛选也产生了明确缺口，旧导出保留，最终重新导出缺口为空。

这些都是工程失败，不是实验失败或假说被否定；未借此改写科学评价规则。

## 预算、归档与可复核证据

复用既有30分钟、100轮模型调用、100次工具额度的工程验证账本，没有增额，没有设置API密钥或付费回退。本轮新增14个模型会话、286,579毫秒；连同原摘要试验累计20个会话、395,231毫秒、21轮、1次工具执行。所有进程已退出，预留归零；新增科研实验为0。

原始材料及各次失败、请求、模型答复、安装票据、真实条目、核验和接续结果位于`artifacts/research-context-model-001/installation-*`。最终只读审计为`installation-closed-loop-final-audit.json`。交流归档为`installation-005/communications-final-complete`，包含20个会话，缺口清单为空，清单哈希见机器回执。原始私有日志仍在受限目录；可见交流归档不包含私有思考和可能含凭据的提供方stderr，也不冒充开发者外部聊天的完整导出。

## 仍未由这次验收证明的事情

闭环由宿主明确触发，还没有把容量判断、自动生成摘要及恢复接成任意负载下的无人值守策略。也没有证明多天科研、所有跨消息代码依赖或任意多轮压缩都保持语义。七项事实和两段引文是本次验收范围，模型复核仍可能犯错。

`provider_payload_verified=false`：本次重读核验的是固定SDK实际投影和真实模型接续，没有独立截取提供方最终序列化请求。P5的多方向并行、全新隐藏科学评价和工作台面板仍按原工作清单验收。

最终组合检查：`uv run python -m unittest discover -s tests -v`共535项，510通过、25环境跳过；日志`/tmp/asr-context-loop-final-verification.log`。Node模块语法及git diff --check通过。固定解码器对三次成功安装的冻结来源重新读取，消息全部一致；被拒绝的004来源确有差异，未被安装。
