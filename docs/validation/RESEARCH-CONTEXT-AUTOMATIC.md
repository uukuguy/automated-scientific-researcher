# 上下文自动维护与接续验收

日期：2026-11-05。当前P5仍在进行，本报告只评价上下文工程，不评价科研收益。

正常路径与恢复路径均已完成真实订阅验收。已实现：既有AAR执行者接收异步容量预警，串行生成摘要、由不同模型会话复核、取得Control一次性安装许可，核验真实原生写入后继续同一会话。普通日志继续异步；控制和安装回执保持同步。所有失败、原件及已用预算保留。

组织运行通过`--context-reviewers`指定已有成员的复核关系，例如JSON `{"lead_1":"lead_2","lead_2":"lead_1"}`。没有配置的成员只观测，不隐式借用其它角色或预算。复核关系、实际材料容量及策略指纹写入运行证据。维护阶段禁用执行工具，不改变科学任务、实验规则和评价权限。

## 实际过程及发现

| 轮次 | 实际结果 | 处置 |
|---|---|---|
| automatic-001 | 自然请求边界发出维护延期；旧笔记因Control版本改变不再有效；收尾误用人类pause命令被拒绝 | 保留原件与成本；增加监督者专用延期，通用流程不自动重新采纳旧科研笔记 |
| automatic-002 | 七项事实保留，但模型沿用已有状态回执，没有第二次工具调用，未触发会话内下一请求 | 增加“正常结束后的预警交给下一角色会话”；不重复工具来制造触发 |
| automatic-003 | 真实摘要及独立复核完成；原生压缩写入后系统上下文核验拒绝，未发送后续模型请求 | 根因是pi合并系统配置增量；改为完整有效配置比较，保留工具/规则变更拒绝；退出后只签发历史核验回执 |
| automatic-004 | 当前状态重新准备及复核完成；pi返回Already compacted，续答0轮、工具0次 | 不先发模型请求绕过；增加受管、无模型的SDK安装子进程 |
| automatic-005 | 摘要、独立复核、恢复安装和同一原生会话续答通过；七项事实全部保留 | 取得Control verified回执后才续答；原始前缀保留 |
| automatic-006 | 正常pi钩子路径自动处理上一会话预警，真实生成/独立复核/原生安装/同一会话续答通过，七事实全部保留 | 无恢复安装分支，未重复科研或提高预算 |

维护替换前后的投影文本字节数分别记录，不当作token容量或科学正确性证明。第五轮替换部分为24578→6922字节；这不是整个原生文件变小，原生日志保持追加。

## 验证与证据

最终601项完整工程检查通过（25项环境跳过），含安装子进程超记录容量留痕、原件保留与零预留收尾，另有真实模型证据。覆盖了请求延期不扣未发轮次、独立会话、复核拒绝、来源变化、未缩短候选延期、实际SDK写入、系统配置增量与快照相等/差异拒绝、历史恢复不授权当前请求、安装前禁止turn准入、受管子进程退出及交流导出。

本轮六次工程验收合计新增397394毫秒（约6.62分钟）、14个模型轮次、3次状态工具调用；原30分钟预算不变。全部35个历史运行会话均已退出，零预留、零待核验安装。最终归档索引226份来源，明确保留第一轮一个未最终写出结果的缺口。

原始证据存于受限`artifacts/research-context-model-001/`。每轮`automatic-NNN/`保留配置、失败或成功、收尾及不可变交流归档；`context-maintenance/`保留来源准备、生成/复核完整交流、候选、安装与退出回执。后续整理不能替代旧失败记录。机读摘要与原件指纹见同目录名的JSON验收摘要。

已知归档缺口：第一轮异常使`steps/automatic-001-generator/result.json`未最终写出。其原始事件、原生日志及维护目录中的`previous-result.json`仍保留；归档明确标注`step_not_finalized`，没有回填伪造完整结果。凭据及私有模型推理不进入公开交流；原提供方stderr与开发侧聊天并非完整导出范围。

## 结论边界

测试复用既有30分钟工程预算，零数值执行额度；未追加预算、未重置消耗、未运行科研实验、未切换付费API。测试预留合计99.99%仅用于短会话触发；生产10%/15%/10%没有改动。失败后的修复、工程笔记更新和历史写入核验属于明确记录的开发侧干预。

这证明指定配置下的真实模型上下文维护和恢复接续链，不证明无人值守多天科研、任意代码引用保真、提供方完整请求容量或真实窗口准确性。SDK用量仍是估算，压缩后可为未知；持久队列、硬内存边界和其它重型来源读取事务拆分仍开放。模型复核意见和七项工程事实回忆不能替代独立科学评价。
