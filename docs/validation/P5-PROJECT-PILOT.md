# P5：研究团队自主完成一次补样比较

这次把项目目标、规范和已有材料交给研究组织，团队自行选择研究方向、生成方法、
实验安排和审查方式。真实计算与报告交付已结束；**独立隐藏评价和训练复现尚未完成，
P5 不因此关闭。**

组织者邀请两个方向负责人：一人提出并实施研究，另一人审查。他们没有照搬历史的
四组八种子方案，而是选择比较“全部针对目标分布补样”和“目标、过渡、全局混合补样”。
两个方案各做四次重复，每次补64个样本。角色会话串行，本轮未使用额外的执行成员，不能据此
声称并行研究组织已验收。

## 实际完成了什么

- 生成并标注512个样本，8个批次全部得到标签，没有补抽或重跑求解。
- 训练1个原始基线和8个增强模型，保留全部结果。
- 共执行24次计算：7次分析、8次标注、9次训练，累计96.833秒计算时间。
- 15次角色会话，其中14次正常结束、1次WebSocket失败；恢复沿用现有登录和预算，
  没有浏览器重新登录、付费API回退或重复计算。记录的模型会话时间约56.54分钟。
- 方向已关闭，两个任务均完成，所有角色进程退出、预留归零、待送达消息为零。

这里“原分布”指原先常见的训练场景，“目标分布（OOD）”指原训练数据覆盖不好的场景。表中的RMSE是均方根误差，用来衡量预测偏差，越小越好；p.u.是按额定量归一化后的单位。

在研究时能够查看的开发测试样本上，定向补样4次全部同时达到目标场景改善和原场景退化不超标两项要求，混合补样只有1次通过。
入选定向模型的 OOD 电压误差下降90.23%，但原分布误差增至约11.45倍；它满足原先
允许的绝对误差增量，并不代表原分布准确率没有退化。

这些结果来自已知条件下的公开32-ID/32-OOD开发样本，入选也使用了这些数据。
四次重复不足以证明普遍优势、因果机制或新方法创新；不能将90.23%写成独立泛化收益。

512个新样本的既有方程和输入保持检查均通过，但**全部存在运行约束越限，每个样本
有186条支路的热限额未评估**。它们是本次任务允许的方程标签，不是安全运行场景。

## 失败和修订没有被抹掉

审查员先发现生成器自检不能识别“修改坐标后重算哈希”的问题，负责人修订检查并
完成负例测试。随后，负责人自己编写的标签审查把初始母线电压误作发电机受控电压，
导致128个断言失败。团队保留旧代码和失败输出，明确修复原因，并在训练前重新检查
全部512行；没有修改标签、物理控制或通过门槛。

四批合并审查还触及16MiB请求上限。系统在执行前拒绝并保留详细回执，团队自行改为
3/3/2批审查，没有重算标签。24个进程成功退出不等于24次科学检查都通过。

旧1MiB快照上限拒绝了2.28MB汇总和大型审查输出。开发侧在外部修复通用快照能力：
默认16MiB，超限记录实际大小、目的、恢复办法和Control回执，不暂停研究或丢弃原文。
当前团队进程仍使用旧实现，原失败记录原样保留。
