# 笔记附件正文流式读取验收

已将代码快照和实验附件正文改为分块完整哈希校验，核验缓存不保留全文。分页使用增量UTF-8解码，扫描全文统计字符和复核哈希，只保留所请求范围。页外损坏或无效编码不能被忽略，提交仍核对文件版本、来源和当前权限。

统一策略第7版新增`artifact_read_chunk_bytes`，默认1MiB，可通过`ControlService(..., capacity_policy_path=...)`显式配置。它控制每次读取缓冲，不限制总文件大小；块读满继续读至EOF。分页回执/事件携带实际值和策略指纹。旧运行时策略可保持原指纹加载；Control显式指定缺字段的旧策略报错，不补值或提高预算。

完整检查663项，25环境跳过，其余通过；最终专项重跑10项流式检查、8项策略检查也全部通过（其中2项策略检查新增）。原附件占锁测试同步覆盖清单读取与正文流式读取，保留实际SDK安装检查。没有模型请求或科研执行。

本机内存测量使用临时库与合成单附件；`tracemalloc`只测Python分配，不包含OS页缓存、进程RSS或并发叠加。默认读取块为1MiB，取页为13字符：

| 正文字节数 | 核验峰值字节 | 取页峰值字节 |
|---:|---:|---:|
| 1,048,576 | 2,126,416 | 2,103,232 |
| 12,582,912 | 2,108,232 | 2,103,232 |
| 50,331,648 | 2,108,208 | 2,103,232 |

10项流式检查覆盖禁止附件整份read_bytes、跨块中文/表情/组合字符、请求页外损坏/无效编码/不完整UTF-8尾部、读取中改写、EOF/越界、事务外读取、显式配置及12MiB正文核验/分页的内存回归。文件原件与材料指纹不因读取块变化而重写。

复现内存测量：`uv run python scripts/note_artifact_memory_probe.py --output <新的结果文件>`。脚本拒绝覆盖已有输出；原始结果及日志在`artifacts/note-artifact-streaming-001/`，源码/日志指纹见同名JSON。

边界：清单仍整体读取和JSON解析，引用/文件数量与核对清单也可能增长；每页需要完整文件IO，不是随机访问。没有新增文件总量上限，既有8000/16000字符分页规则未改；上述Python测量不是生产内存上限或任意负载保证。
