# P5：团队亲自实现并评审坐标生成器

本次把上一轮团队提出的采样方案变成了实际程序：方向负责人提出实现验收方向，组织者批准，两个 worker 分别实现和做对抗检查。两个隔离分析任务均已成功执行，原始证据完整。它证明了团队可以交付可运行的研究代码并发现自己的测试漏洞；没有证明样本能提高训练效果，也不表示 P5 已完成。

## 做成了什么

- 实现 worker 根据原提案写出独立生成器，使用 8 个固定种子、5 类命名样本块，得到 768 个不同坐标。跨实验组复用后对应 2048 个拟议求解槽位；本次没有求解或生成新标签。
- 实际执行了重复运行、标签删除／污染不变性、取值范围、数量、共享块和公开坐标碰撞检查。
- 另一个 worker 阅读实际源码和输出，用独立检查条件验证顺序，并注入非法输入、公开坐标碰撞和错误实验组顺序。评审分析包含 12 项预期观察，包含成功暴露漏洞，而不是 12 项“代码无缺陷”。
- 两次分析共用 3407 毫秒计算时间。计算、任务、假说版本、源代码快照和原始输出均有明确引用。

## 一个有价值的失败

把 TT 组的块顺序从 T0、TA、TB 改成 TB、TA、T0，生成器自己的检查仍然报告通过。原因是生成和检查都读取同一个 ARMS 配置；配置错了，双方会一起错。

交付的固定源码本身使用正确顺序，且通过评审者另写的字面顺序检查。因此可有条件接受这份固定产物，但不能信任任意版本的自报 accepted。缺陷保留，未冒称已修复。下次修改必须有独立的冻结协议检查和错误顺序回归测试。

评审角色使用了独立检查逻辑，但仍复制生成器作为被测对象；这不是独立电气验证器，也不是泛化评价。跨种子／跨块碰撞注入、仅六位舍入碰撞注入、桥接随机数调用计数和跨版本复现尚未执行。

## 边界与下一步

有效契约只允许 analysis；即使任务错误授予 label 或 fit，Control 仍拒绝执行。新标签额度为零。拟议 paired_sampling 输出是描述格式，尚不是 Control 接受的正式协议。

下一步应先将固定坐标转成正式契约并独立校验顺序、数量、共享关系和来源，再冻结新的比较预算与评价材料。原 3584 槽位科学比较没有获此次运行自动授权；不得重新打开 P4 或旧设计运行、复用已知评价集冒充新的隐藏测试，或把这里的自检当作训练收益。
