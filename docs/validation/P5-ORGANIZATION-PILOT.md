# P5 组织与设计试运行：验收记录

2026-11-03。此轮完成了真实的串行组织／设计协作，**P5整体仍未完成**。

## 发生了什么

组织者没有预设两个科学部门，而是先请一位负责人提出方向。负责人根据P4材料提出：先区分目标附近采样、桥接采样和全局采样各自的作用，再判断是否需要主动采样与困难求解层。组织者启用这一方向，负责人委派一位worker审查实际代码和实验规则。其余两个名额没有被强行使用。

交付包括四组配对采样的下一轮实验方案、未运行的采样账本代码、worker审查、组织者交叉审查，以及逐项修订回应。审查找到了失败样本输入绑定不足、数据可在检查后被修改、无效标签状态转换不完整等具体问题；负责人修改源码并保存新快照。组织者读取修订文件后关闭该设计方向。关闭方向不代表解决了数值研究问题。

图中的双层架构保留了人类建议的来源。团队没有照图设岗位，也没有声称P4已经证明困难求解层必要。其建议是先做能分辨不同解释的静态采样对照。

## 运行与恢复

实际调用pi 1.5.0、openai-codex订阅模型gpt-6.1-sol和固定版本AAR循环。12个会话尝试中10个正常结束；首次令牌失效、一次WebSocket错误各保留一次失败。浏览器只在认证失败后重新登录；WebSocket错误没有触发登录。两次恢复均沿用原run与契约，未增加预算。

共享模型时间使用1,019,882 / 1,200,000毫秒，77 / 160轮，130 / 320次工具调用。计算次数和计算时间均为零。12个进程全部退出，预留全部释放，待交付通知为零，Control与AAR投影保持暂停供后续验收。一次宿主生成的收尾消息使用human权限，其来源写入回执；未由开发者指定科学方向或代写研究产物。

实际角色为组织者、一个负责人和一个worker。此次执行是串行的，不证明多进程并发、不同runtime混用、多个负责人直接互评或同预算团队收益。

## 工程检查与认证修复

完整工程测试共345项，325项通过、20项因环境条件跳过；其中组织相关24项通过。模型执行证据与mock工程检查分别记录。独立工程审查子进程因本机配置的模型不可用而未启动，不计为完成；本地代码检查及完整测试已执行。

针对用户指出的重复登录，修正了角色缓存凭据优先且刷新不回传的问题。统一认证来源默认是`~/.pi/agent/auth.json`，也可显式指定。会话开始从来源复制当前Codex OAuth；进程结束后在短文件锁和比较检查下回写刷新结果，仅修改该provider。新的外部登录不会被旧会话覆盖；冲突、锁占用或I/O失败留痕并暂停，不自动打开登录页。对话、工具配置仍按角色隔离，子进程继续禁止API密钥。

本轮成功登录的凭据已在同账户检查后归并到统一来源，其他provider不变。这项修复由回归测试验证；前述已完成模型轨迹使用修复前加载的运行代码，不冒称已完成新认证逻辑的长周期令牌轮换验证。多个独立ASR进程同时触发OAuth轮换仍需进一步验证，不能把文件锁和冲突检测说成完整并发认证代理。
