## 1. 目标与范围

**已确认**：建设可持续运行的自动化科研系统。电网运行样本探索与潮流求解方法研究是首个应用课题，首份科学交付可以来自其中任一方向或其组合。

需求方反馈问题“不完全是训练样本泛化，甚至是发现新方法”。此前具体业务含义不完整；D025 进一步明确当前训练增强任务，长期仍保留样本生成与求解两条研究方向；不能据此预设必须发明某一种算法，也不能把成果限于采样参数调优。
人确定课题范围、变量权限、评价规则和预算。研究员在该范围内自主选择采样与求解方法、安排实验、分析失败和修改假设。
**2026-11-03 目标澄清（D023）**：“找出新方法”要求超出检索并试用已有算法。已有方法、文献和复现构成知识与比较基线；研究员应从实际问题与失败证据形成假说，提出有实质区别的方法或机制，并以相关基线、必要消融及独立复核检验贡献。不得预先替研究员选定求解器改进路线，也不得把已有算法的重新实现、简单组合或 Agent 生成代码本身称为创新。探索阶段允许形成问题；正式验证前冻结假说、方法与评价规则。允许负面结果，但必须如实标明新方法目标是否达成。
研究员可以提出扩大范围的建议；初版不自主决定跨课题资源分配。
**当前优先级（2026-11-03，D024）**：先做现实的 OOD 样本生成。新方法目标保留，首个可用数据闭环不以先发明算法为前提。先明确参考分布、物理与运行语义、可解释的分布偏移及数据用途；实际数据缺失时只称物理约束下的合成场景，不能称真实运行分布。具体采样方案仍待验证，见 P4 计划。

**当前课题含义（2026-11-03，D025）**：某一可训练求解方法在特定 OOD 样本上效果不好；研究相关分布的额外训练样本是否改善泛化，以及如何生成这些可用样本。训练收益是假说，不是前提。OOD 相对原训练分布定义；用于诊断和增强的样本不能再充当独立测试证据。生成数量和覆盖率是辅助指标，主要证据来自增强训练后目标方法在独立同类分布样本上的表现，并检查原分布退化。目标方法与可信标签生成/复核工具分开。人类给出这一层问题拆解及可用材料、授权；Research Lead 负责进一步诊断、相似性定义、方法选择和实验设计，不要求人类先写完整研究方案。目标模型、训练接口及数据的具体形式仍需取得，不能以替代模型结果宣称解决实际任务。

**项目委托方式（2026-11-03，D026）**：当前由开发侧模拟人类研究员的真实项目，准备目标模型、原始训练材料、OOD 诊断证据和验收标准，将问题交给 ASR 解决，不再以等待真实客户提供材料作为当前前置条件。开发侧负责可信实验能力与独立验收，AAR Research Lead 自主负责诊断、假说和增强方案。模拟项目结果不冒充未知真实业务效果；准备数据和接收项目不等于完成训练增强任务。

**当前实验能力**：`ood-study-development/1` 为同一个 Control 账本和 Supervisor 增加隔离 Python 分析、按研究员坐标标注、冻结训练程序重训三项能力。开发侧不实现研究员的采样方案。批次角色在提交时固定；探针、原始诊断材料和分析代码输出不能转成训练标签。每个批次预留执行预算与样本额度，失败及部分输出保留。真实容器已验证 64 样本标注、基线训练复现、隔离和超限记录；同一 AAR 研究员随后已实际完成 704 个新样本标注和 9 个增强模型训练，工程故障及消耗保留。开发 profile 不授予最终测试访问权；独立评分已在冻结选择后完成真实隐藏测试：主模型 OOD 电压 RMSE 下降83.23%，ID误差约增至11.02倍但满足预定绝对容差；选定训练已精确复现。P4合成客户项目闭环完成，证据见 `docs/validation/P4-SCIENTIFIC-RESULTS.md`。最终AAR报告已实际写出；会话达到时间上限前未发布快照，控制侧以明确归档身份保存原文和候选结论。上下文轮换仍需操作侧恢复；不能称完全无人值守闭环或真实业务收益。

任务书 `docs/IEEE118_OOD_Sample_Expansion_Task_v2_2.md` 是研究参考。用户决定优先于任务书中的顺序、时间和技术选项。

初版必须完成：单研究员提出问题、执行真实实验、保存证据、提交发现、独立重跑，以及中断后的恢复。
多研究员规模化、跨拓扑能力、学习型求解器和真实业务迁移不作为首个工程闭环的必交功能；用户可以通过课题契约开放相关探索。通用领域插件市场不属于初版范围。

## 2. 设计选择

采用“最小领域实验环境 + 尽早接入单研究员”。
先建立可信的数值执行与验证入口，然后立即接入 AAR。无需先实现全部研究算法。
保留 AAR 的研究循环、论坛、共享发现和代码快照能力；分离原有 W2S 任务依赖。
不把所有平台组件重新实现一遍。新增能力以现有组件扩展和薄适配为主。

不采用完整平台优先路线：其部署、训练依赖和界面改造会延迟真实反馈。
不采用全部电网算法完成后才接 AAR 的路线：它不能及早验证工具是否适合自主研究。

## 4. 职责与部署

- AAR：自主研究会话、论坛、共享发现和代码快照；已有用户查看入口可用于初期调试。面向人类研究者的工作台职责见 §9.2。
- 实验服务：接收数值实验请求、核对课题契约、分配预算、执行工具、保存原始证据。
- 电网领域模块：场景结构、潮流调用、原方程残差、运行约束、覆盖指标。
- 独立评价执行器：读取冻结代码与配置，在独立环境中重跑；产生验证报告。

**已确认**：研发阶段使用本机 OrbStack 的 Docker Engine 和 Docker Compose，不额外创建虚拟机，不引入云集群或消息队列。
研究员、实验执行和验证使用职责分离的容器；并非每个场景必须创建一个容器，一批场景可以属于同一次实验执行。
调度组件管理容器生命周期；研究员不直接获得 Docker 管理接口。证据存储在容器生命周期之外。
后续可迁移到 Linux 主机或云虚拟机；额外虚拟机不是当前的前置依赖。
研究员工作区可写；canonical case、验证代码和正式评价数据由服务端管理。
正式自主运行使用容器或等效 OS 隔离，限制挂载和访问权限。仅目录分隔不能声称实现独立权限。
本机进程模式可用于调试；不能据此验收正式评价隔离。
本机采用原生 `linux/arm64` 作为建议构建目标。跨架构镜像分别记录环境并复核结果；模拟运行与原生运行的性能指标分开报告。
运行可用性、实际隔离和数值工具验证证据见状态文件，不能以部署设计替代运行验收。

开发数值路径采用 MATPOWER 8.1 / Octave 7.3.0 + Python 编排，原生 arm64 参考镜像、case hash 和包清单已记录在 `configs/numerical-environment.json`。执行按固定镜像 ID 重放；APT 构建源尚未固定为历史快照，重建镜像需要新环境记录与重新验收。
若参考路径受阻，可先用明确标记的替代实现调试接口；替代路径不能直接获得参考一致性验收。
**已确认（2026-11-02 更新）**：研究员运行时可替换，主要使用用户已有订阅的 coding agent，避免默认按 API 用量计费。增加 pi 作为轻量基准运行时，优先验证其 Codex 订阅登录路径；Claude Code、Codex 及 Grok 相关运行时按实际可用的官方程序化入口适配。账号订阅不自动证明 SDK 可使用订阅额度。

运行时适配负责启动、事件、工具、指导、停止和会话恢复；ASR 保留课题、预算、实验与证据身份，AAR 研究组织和协作能力独立于具体模型。认证方式与计费方式显式记录。订阅额度耗尽或限流时暂停并保留恢复状态，不自动切换付费 API。API 模式只在单独明确授权时启用。订阅运行仍限制墙钟时间、会话/轮次数和实验工具消耗；供应商未提供剩余额度时记录 unknown，不伪造无限额度或精确费用。

**已确认（2026-11-03，D021）**：订阅型 LLM runtime 禁止设置或向子进程传递任何 `*_API_KEY`。唯一例外是 pi 明确使用非 `openai-codex`（亦记为 `openai_codex`）provider；该例外不授予付费 API 使用权，仍需显式计费授权与预算。运行时启动边界必须执行此约束，不能仅靠 prompt。

运行时边界和各适配器验证状态见 [研究员运行时](architecture/RESEARCHER-RUNTIMES.md)。本决定替代此前“初版固定沿用 Claude Agent SDK”的技术建议。pi 基准接入不等于所有订阅运行时已完成验证。

### 三层研究组织与 Capstone

**已确认（D018，修正 D017）**：Super Agent 是架构名称，角色称为研究组织者（Research Organizer）。它统一与人类研究员沟通，理解总体目标，协调整个 AAR 研究组织，安排跨方向优先级并汇总进展、冲突及需要人决定的事项。它不与方向级科学指导合并为一个“总导师”。Capstone 对接研究组织者。

AAR 内可有多个方向负责人（Research Lead，原称导师），分别负责方向级科学指导、假说质询、实验设计评审、互补探索及正反证据综合。多个研究执行者（Research Worker）承担检索、候选实现、实验、调试、审查等具体工作。方向负责人继承此前自主研究员的科学职责：自主提出问题、假说、方法和研究计划，依据证据修正方向；可将实现和实验交给 worker，而非退化为流程审批者。多个方向负责人可以直接讨论、交叉评审及综合矛盾证据，不要求所有通信经研究组织者转发。具体任务可复用不同专业 worker；每项任务必须保留唯一负责关系，不能让多层同时推进同一执行。

**已确认（2026-11-03，D027）**：研究方向的划分是科研决策，由研究组织者根据委托、材料和证据提出，与方向负责人讨论后推进；开发侧不预置方向主题或强制填满岗位。负责人可建议新增、拆分、合并或终止方向，组织者在既定范围、权限和预算内协调调整，超出授权边界再交人决定。并发名额与方向数量分离：最多两个活跃负责人不等于必须存在两个固定方向，也不禁止更多方向排队。每次调整记录理由、证据、任务归属和资源变化。

图示“可行域发现与主动采样＋困难样本求解”属于人类提供的候选研究架构，不是已实现的ASR核心架构或P4研究员原创成果。P5团队可以采纳、修改或否定它；不要求两层对应两位负责人。项目代码中的生成器、困难求解策略和反馈结构可由研究团队设计与实现，正式评价、隐藏材料、权限和预算仍由系统治理。P4没有验证主动边界学习或困难求解层的必要性，不能把实现双层结构本身当成科学成功。详见 [P5组织研究计划](plans/P5-RESEARCH-ORGANIZATION.md)。

每个 Research Lead 拥有自己的外层研究 agent loop，维护目标、假说与证据，自主决定实验、委派、评审、修订和停止建议。Runtime 的内层推理/工具循环完成具体工作；研究组织者协调方向但不逐步驱动 Lead。Control/Supervisor 从外部执行预算、权限、派发与停止约束，不形成另一个科学决策循环。当前 P3 验证的是有界 AAR loop 调用及恢复，并非已部署无限持续的多 Lead 服务。

AAR 继续承担研究循环、方向负责人/worker 协作基础，复用共享发现、论坛、快照及实验组织。研究组织者连接人和这套组织，不再创建另一套竞争的实验调度账本。Runtime 提供模型及工具会话；ASR Control 负责契约、权限、预算、派发与回执，实验服务保存原始证据，独立评价器负责核验。

Capstone 只持有交互和展示投影。讨论转成明确目标、任务、指导或变更建议后，由 Control 执行授权并返回正式版本/回执；人类可直接暂停/停止，不必等待研究组织者或方向负责人。任何智能体均不能自行提高授权预算、改变正式评价规则或代替 evaluator 宣布科学结论通过。代码审查 worker 不等于独立科学评价器。

### 5.2 变量控制模型

每个变量包含：默认值、有效值、控制模式、允许范围、修改权限、生效范围和变更记录。

- `fixed`：在当前契约中固定。智能体可以提出修改建议，不能自行改变。
- `bounded`：允许智能体在显式数值区间或候选集合内修改。
- `open`：允许提出和实现新方法；仍受问题语义、资源预算及执行权限约束。

用户可以修改变量模式和方向。更改产生新的契约版本；正在运行的 trial 保持启动时版本，除非用户明确停止并重新提交。
智能体在已有许可范围内试验无需逐次审批。跨越许可范围应提交有证据支持的建议。
默认值合并用户配置后形成完整、可执行的契约。参数缺失或范围冲突时，执行入口必须报明原因，不得悄悄使用工具默认值。

同一契约用于研究员提示词、执行前检查和结果解释。方法变量可在一次研究中变化，正式比较的评价规则保持版本一致。

### 5.3 比较与变更语义

- 修改负荷、出力或拓扑：记录为场景变化，不宣称解决了原来的固定输入。
- 修改初值、算法或数值实现：可作为同一输入上的求解方法比较；独立验证仍回到原问题。
- 修改负荷模型、控制政策或 Q 限值处理：检查是否改变数学问题，必要时形成新的问题定义和独立结果组。
- 求解器内部容差、迭代上限和停止条件允许研究；最终独立验证阈值在同一评价协议内固定。
- 用户可修改评价规则、分布和预算；新规则产生新协议版本，旧结果不得被静默重算或重新解释。

比较采样器时使用相同参考求解协议；比较求解器时使用同一组输入。
采样与求解联合方法通过交叉对照识别贡献，并计入热启动参考解、多次尝试、训练和延续路径的成本。
允许方法输出替代方程或中间状态，但最终有效性必须由原始问题的验证决定。

初值、历史解、训练标签和中间信息的来源及获取成本必须记录。禁止把正式评价数据作为候选方法开发资料。

输出标签分别记录：输入有效性、求解状态、方程验证状态、运行约束状态、OOD 分组。
未知或未找到根不能改写为物理不可行。
未提供运行约束的项目必须标记未评估，不能算作运行可行。

指标分别展示：唯一方程有效样本、唯一运行可行样本、预定义特征分区覆盖、重复率、计算成本。
覆盖指标只是代理指标；完整可行域未知，不报告未经支持的“全可行域覆盖百分比”。
20–50 个固定种子场景用于管线验证。研究比较所需规模根据成本和波动校准。

## 6. 身份、数据与状态

区分三种身份：

- `research_run_id`：一个研究员在一个课题上的持续工作，跨会话恢复时保持不变。
- `trial_id`：一次冻结输入和配置的数值实验，可包含多个 scenario。
- `attempt_id`：同一个 trial 的一次执行尝试；重试分配新 ID，不能覆盖前一次结果。

现有 AAR Experiment 对应研究运行的编排记录。新增数值试验清单关联该记录，不建立第二套研究员调度数据库。详细设计采用本机单控制写入服务扩展上游 SQLite；Supervisor 仅执行受理后的派发意图，Capstone 仅保存投影。该技术选择已有实际上游 ORM 同库映射和原子性测试，见 P2 验收记录。

服务端试验清单保存：契约版本、作者、代码快照 hash、输入 hash、参数、种子、求解器和验证器版本、请求预算、状态事件和产物 hash。
结果保存逐场景终止原因、耗时、迭代、残差、约束违反和日志路径。
采集不到的轨迹明确标记 unavailable，不能伪造迭代数或诊断值。

执行状态：queued → running → succeeded / failed / timed_out / cancelled / interrupted。
succeeded 仅表示执行与产物写入完成，不代表方法有效，也不代表每个场景收敛。

先持久化请求和预算预留，再启动执行。相同幂等键和相同请求返回同一 trial；同一键但不同请求拒绝。
产物在临时目录写入，完成后校验并原子发布 manifest。无终态 manifest 的目录不能作为完成结果读取。
原始产物一经发布不再覆盖。更正和新解释通过关联记录追加。

### 6.1 科研语义与假说演进

**已确认（D016）**：失败必须留下可分析证据，但不保证每次失败产生科学发现。执行结果、实验设计/材料有效性、假说证据判断和发现复核状态分别记录。未支持不等于被否定；无效实验不能作为否定假说的充分证据。科学负面结果不进入基础设施错误自动重试。

Research/Run 与 Runtime Session 分离。在 Trial、Attempt、Evidence、Finding 基础上持久化独立不可覆盖的 Hypothesis revision，记录预测、适用范围、反驳条件、探索/验证属性及修改理由。trial 冻结时绑定假说版本与评价协议；finding 关联支持、反对或不确定的证据以及 Validation 报告。后见分析必须显式标记，不能回填成实验前预测。

同一冻结实验的基础设施重试创建新 attempt；方法、输入或评价变更创建新 trial/版本。假说变更保留父版本和理由，不能通过改代码或改判据重写旧实验结论。复用已有证据进行新解释时追加引用及来源，不修改原始记录。恢复从持久化对象及证据关系重建，不依赖会话摘要。

**实现边界**：P3 首个切片已提供 Hypothesis 修订发布/查询、trial 可选冻结绑定、候选发现的支持/反对/不确定关系及后见分析标签；无绑定历史保持显式未关联。pi 工具/state 可读写假说，AAR 论坛投影保留关联。作者关系仍是作者声明。新增 evaluator 专用不可覆盖 Validation 记录，绑定 terminal trial/attempt、原始 manifest 和评价引用；分开保存实验/方程/运行约束/复现/泛化/假说判断，保留负面历史及显式后见解释。研究员可读取但不能发布验证报告。服务校验身份与证据字节，独立性仍标记为 evaluator attestation，不据此声称已证明隔离或科学结论；完整复核生命周期和发现晋升继续实施。已完成 P2 的验收范围不追溯改写。

## 8. 预算、停止与恢复

**已确认（D016）**：模型访问/订阅额度与实验计算资源使用两个逻辑账本，由同一 Control 原子准入，并受课题总策略约束；不创建两个互不协调的预算权威。不同单位不能直接相加。模型账本记录认证/计费模式、调用消耗、配额观测与限流；计算账本记录实验、CPU/GPU 时间及实际资源消耗，配合并发和单次资源上限。审批针对计费方式切换、超出授权预算或新增权限，授权范围内不逐步审批。

**上限治理（D022）**：每个上限需说明控制目标、单位/作用域、配置位置和缺省值适用性；验收时限不冒充长期科研缺省值。超限记录上限、配置值、实际/请求值、对象身份、动作、保留证据与恢复办法。普通耗尽进入可恢复暂停；只有资源隔离或失控进程需要强制结束当前执行，并保留课题。预留清理/检查点时间，禁止静默失败、静默截断和自动计费回退。提高上限必须记录新策略版本，不得清除历史超限或重置消耗。当前实现清单见 [上限审计](validation/LIMITS-AUDIT.md)。

供应商剩余额度不可见时记录 unknown，并执行本地时长/轮次上限；不能把未知当作无限。不得自动回退付费 API。当前已在原权威预留/结算行上提供 model/compute 两个逻辑快照及跨组原子预留，保留历史消耗与未知在途预留，不重复建账；已增加带来源/时间的配额观测和未知状态保护；未接入 GPU 的强制限制仍待实现。

分别限制研究会话时长、单次数值实验时长、累计求解尝试数和研究模型调用预算。
每次重试、延续路径中间求解和验证调用分别记账；同时报告总耗时和资源环境。
请求前预留预算，结束后结算；并发请求不能超额分配。已消耗预算在失败时不退回。
模型费用若依赖延迟上报，只能作估计；不能宣称精确硬美元上限。记录未结算调用，禁止静默无限重试。

超时由外部监督程序处理活动会话和子进程，不能只在会话之间检查。
连续基础设施错误达到配置上限后退出并报告原因。科学负面结果不等同于基础设施错误。

恢复时核对进程启动标识、心跳和执行记录；不能只用 PID 判定运行状态。
无法确认存活时先关闭受影响入口并对账，无法恢复的 attempt 标记 interrupted，保留部分产物。确认旧执行已退出或被接管前，不释放预留或启动替代进程。显式重试创建新 attempt。
已完成 trial 不因 Agent 重启自动重复执行；预算与证据身份跨会话保留。

## 9. 评价与研究自主性

开发环境允许详细反馈和反复实验。正式评价在策略冻结后使用未参与开发的场景族。
反复反馈给研究员的集合只能称开发/验证集。

采样器提交可运行策略，由评价端在受控预算下执行，不能只提交挑出的成功样本。
候选代码在隔离执行环境运行，不可读取正式标签、评价器凭据或修改评价规则。
评价器重算指标；研究员填写的指标只是声明，不能作为权威数值。

**已确认（D016）**：独立性分别验收执行权限隔离、冻结原始材料来源和关键数学逻辑独立性。评价器根据冻结的原问题重建方程和约束，不复用未经交叉检查的候选指标实现。现有 Python 电气检查与 pandapower 交叉校准不等于独立评价环境隔离已验收；缺失约束保持未评估。

区分两种复核：

- 复现：相同冻结输入与配置，在干净环境重跑；数值采用预先固定容差，运行时间不要求一致。
- 泛化检查：在未参与开发的场景族和种子上执行冻结策略；需单独报告，不能以重跑替代。

算法与验证器不得完全复用同一条未经交叉检查的残差计算路径。
至少用故意扰动的电压、单位/索引错误、输入被改变、越限案例检查验证器是否会错误放行。

研究员自行选择阅读、诊断、实验与实现顺序。系统只约束可执行契约、证据、资源与身份权限。

### 9.1 人类研究者介入机制

**已确认基本设定**：人类可以在任何时刻观察、提问、补充信息或发出控制指令。系统在关键事件提供介入入口；这些事件不是每轮必须通过的人工审批步骤。下述具体协议与界面仍是实现设计，尚未验证。

| 介入节点 | 人类可以做什么 | 建议默认行为 |
|---|---|---|
| 课题启动或重设 | 明确目标、变量模式、资源额度、评价规则、停止条件 | 已授权契约内启动；缺失执行必要条件时只询问缺项 |
| 假设提出与方法选择 | 提供领域知识、文献、反例；推荐、排除或提高某方向优先级 | 异步指导；契约内探索继续 |
| 实验设计与扩大规模 | 检查对照是否公平、补充场景、调整变量范围或预算 | 小实验自主运行；超出授权边界的部分等待决定 |
| 实验运行期间 | 查看状态与日志；停止新提交、取消指定实验、修改后续任务 | 已启动实验保持原契约；改变在明确边界生效 |
| 异常、停滞与证据冲突 | 解释物理现象、纠正假设、决定修复、转向或增加资源 | 一般数值失败自主诊断；预算耗尽或必要权限缺失时暂停受影响工作 |
| 候选发现形成 | 质疑结论、指定反例或消融、请求独立复核 | 主动通知并展示证据；无回复不等于认可 |
| 阶段复盘与成果交付 | 调整方向、选择投入重点、审查科学意义和结论范围 | 按约定事件或周期复盘；对外发布另按用户授权执行 |

交互分为三类，避免自然语言评论被错误执行为控制命令：

- **交流与注释**：提问、解释、领域经验和资料；不自动改变运行契约。人的专业判断记录来源，仍与实验事实区分。
- **研究指导**：优先级、变量范围、预算与方向调整；系统显示解读、目标对象、有效版本和生效点。仅在影响不明确时澄清，不重复确认已清楚授权的操作。
- **运行控制**：暂停提交、取消实验、恢复或结束课题；返回实际执行状态。收到请求不等于已经停止进程。

建议默认采用异步指导与事件通知。用户可为指定课题设置更强的审阅节点；不要求每次提出假设或修改代码都等待人。
同一个请求可能仅阻塞一个实验或一个方向，其他已授权且不依赖该决定的工作可以继续。等待回复期间不能自动提高权限或预算。

介入事件记录：作者、时间、指向的课题/研究运行/实验/发现、原始内容、系统解读、契约版本、执行状态和生效点。
已过时的回复必须核对目标版本；无法安全适用时重新澄清，不能直接覆盖新决定。
人提出的新问题和资料可关联现有实验，研究员应说明采纳、待验证或未采纳的理由及证据。

修改规则：

- 新范围或新评价协议生成新契约版本，作用于后续实验；旧实验结果保留原条件。
- 默认“暂停研究”停止提交新实验并暂缓排队实验派发，允许在途实验完成并保存证据。明确“立即停止”则取消目标进程并保留部分产物；这两个动作在界面中分别显示。
- 取消与完成并发时，以持久化执行事实为准；不能删除已完成结果或误报取消成功。
- 恢复从实际实验状态和剩余预算开始，不依赖研究员对上次会话的文字记忆。
- 不依赖手工编辑服务器文件或重启整个系统完成正常干预。

建议首版入口：课题对话、变量/预算配置、实验列表及日志、发现与复核视图。
人类工作台采用 Capstone 的专属科学研究模式（§9.2）；AAR Forum 和 Dashboard 保留为已有研究协作与调试能力，避免同时建设两套面向人的控制中心。需要补齐控制指令、权限、生效点和回执；聊天消息本身不等于控制接口。
通知频率、停滞判据、具体审阅节点和 UI 形式仍待确认，不预设为已实现能力。

已确认职责划分（具体接口为实现设计）：

- **Capstone 科学研究模式**：课题对话、材料、变量与预算编辑、方向指导、运行观察、发现质询和复核入口。它可解释与整理证据，但不能自行宣布数值验证通过。

1. 课题可关联多次运行、多段对话；一次运行包含多个 trial 和 attempt。使用显式映射，不把 Capstone turn/attempt 与本项目运行或实验身份直接等同。
2. 长期研究在工作台断线或一轮对话结束后继续；用户仍可提问、发送指导和控制，无需等自主研究结束。
3. 控制请求带幂等键、目标与预期版本。界面区分已接收、待生效、已执行、拒绝；只有执行端确认才能显示已暂停或已取消。

5. Capstone 展示可恢复的状态投影和事件；运行、预算、实验与正式复核各有唯一写入责任方，不双写两个权威账本。

首个适配切片建议：创建课题并配置研究变量 → 启动一个 AAR 研究运行 → 运行中追加指导/暂停新提交 → 查看真实 trial 与候选发现 → 请求独立重跑并查看回执。刷新或断开工作台不会丢失运行；重复控制请求不会重复执行；指导是否采纳有记录。

完整可视化假设图、多研究员协作和复杂报告编辑可后续增加。P1 的真实数值环境仍是底层前提；工作台适配不要求先完成整个 Capstone 企业研究功能。

## 10. 首个端到端验收

1. 固定一个小型真实 IEEE-118 基线并验证原方程残差。
2. 单研究员读取基线，提出一个可检验的问题并运行诊断实验。
3. 实验服务保存完整证据；研究员提交带证据引用的 finding。
4. 在执行途中及结果发布后分别注入中断；验证状态恢复、幂等性和预算保留。
5. 独立执行器从代码快照和 manifest 重跑，生成一致或不一致的明确报告。
6. 研究员读取复核结果，决定继续、修改假设或记录负面结论。

系统验收可以由可信的负面结果通过。科学成果验收需额外满足同预算对照和独立场景证据。
没有真实模型调用，仅使用脚本模拟研究员，最多证明工程链路，不能宣称自主科研通过。
没有真实潮流计算，仅使用假求解器，最多证明接口与恢复机制，不能宣称电网实验通过。

## 11. 实施顺序

- P0：设计与源码映射。完成当前文档和工作清单对齐。
- P1：可重放的真实领域实验。固定上游来源与数值环境，建立 trial 证据、验证和幂等执行。
- P2：单研究员闭环。适配 AAR 提示词和工具、共享发现、外部停止与恢复。
- P3：独立复核与系统验收。验证隔离、故障恢复和重放；形成第一段可信研究轨迹。
- P4：面向新方法的首份科学研究交付。先形成知识基线、问题与假说，再开展样本生成、求解方法或联合研究；正式比较前冻结协议，以对照、必要消融及独立评价检验贡献，诚实报告负面结果与未达成目标。
- P5：三层研究组织。Capstone 对接研究组织者（Super Agent），统筹协同 AAR 内多个方向负责人及研究执行者；验证跨方向证据、唯一任务责任、预算和独立复核边界。

每个阶段有可运行验收；不按任务书算法清单机械推进。

### 11.1 推进顺序与风险约束

科学可信性为最高风险：正式评价规则由授权用户及评价端治理，研究员只能提出变更；新规则产生新版本，不能覆盖旧实验。执行完成、求解收敛、方程有效、运行可行、独立复现和科学发现分别判定；复现不替代泛化。

AAR 适配与系统复杂度为高风险。保留研究循环、论坛、共享发现和快照，具体任务提示与工具由 ASR 契约/领域包提供；固定上游版本并保存可复现补丁，不让 W2S/PGR 训练目标成为通用科研约束。每次变更检查实际激活路径，不能仅因源码残留名词就认定行为耦合，也不能仅改名称就宣称解耦。

P3 持续以一个真实研究切片约束建设范围：提出可检验假说 → 在隔离环境编写候选方法 → 真实实验 → 分析/修正假说 → 证据关联发现 → 独立复核。可信负面结果同样有效；探索过程不强制每次按固定顺序执行这些动作，但端到端验收必须证明相应能力。仅为该切片添加所需的隔离、身份、预算和证据能力；多研究员、分布式调度、插件市场不提前建设。

当前 P2 已证明模型驱动的参考参数实验、快照、候选发现与恢复；没有证明任意候选方法执行、假说迭代或正式独立复核。P3 新增基础设施只有接入上述链路并产生验收证据才算完成对应能力。

## 14. 持续对齐规则

1. 用户确认新的目标、边界、默认值或架构选择后，在同一轮工作中更新本文件的相关章节。
2. 尚未确认的建议放入“建议默认值”或“待定事项”，不得写成已确认决定。
3. 改变已有决定时，先修改当前设计，再在 DECISIONS 追加原因、来源和替代关系；不只在日志尾部补一句。
4. 同步检查 WORKLIST、实施计划、配置和测试。尚未实现的改动列为待执行工作，不能报告已生效。
5. JOURNAL 追加事件；跨恢复边界刷新 RESUME；CURRENT-STATE 只保留结构与入口。
6. 每次实施、恢复工作和阶段验收前先读本文件，并检查它与实际代码是否一致。
7. 使用 Git 保留设计演进。平时更新此稳定路径，不再为每次讨论复制一份完整日期版设计。
8. 旧设计保留显著跳转标记；原始任务书保留原文作为背景。二者均不作为当前边界的权威来源。
