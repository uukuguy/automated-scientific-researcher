## 1. 目标与范围

**已确认**：建设可持续运行的自动化科研系统。电网运行样本探索与潮流求解方法研究是首个应用课题，首份科学交付可以来自其中任一方向或其组合。

需求方反馈问题“不完全是训练样本泛化，甚至是发现新方法”。具体业务含义尚未完全明确，因此保留样本生成与求解两条研究方向；不能据此预设必须发明某一种算法，也不能把成果限于采样参数调优。
人确定课题范围、变量权限、评价规则和预算。研究员在该范围内自主选择采样与求解方法、安排实验、分析失败和修改假设。
研究员可以提出扩大范围的建议；初版不自主决定跨课题资源分配。

任务书 `docs/IEEE118_OOD_Sample_Expansion_Task_v2_2.md` 是研究参考。用户决定优先于任务书中的顺序、时间和技术选项。

初版必须完成：单研究员提出问题、执行真实实验、保存证据、提交发现、独立重跑，以及中断后的恢复。
多研究员规模化、跨拓扑能力、学习型求解器和真实业务迁移不作为首个工程闭环的必交功能；用户可以通过课题契约开放相关探索。通用领域插件市场不属于初版范围。

## 2. 设计选择

采用“最小领域实验环境 + 尽早接入单研究员”。
先建立可信的数值执行与验证入口，然后立即接入 AAR。无需先实现全部研究算法。
保留 AAR 的研究循环、论坛、共享发现和代码快照能力；分离原有 W2S 任务依赖。
不把所有平台组件重新实现一遍。新增能力以现有组件扩展和薄适配为主。

不采用完整平台优先路线：其部署、训练依赖和界面改造会延迟真实反馈。
不采用全部电网算法完成后才接 AAR 的路线：它不能及早验证工具是否适合自主研究。

## 4. 职责与部署

- AAR：自主研究会话、论坛、共享发现和代码快照；已有用户查看入口可用于初期调试。面向人类研究者的工作台职责见 §9.2。
- 实验服务：接收数值实验请求、核对课题契约、分配预算、执行工具、保存原始证据。
- 电网领域模块：场景结构、潮流调用、原方程残差、运行约束、覆盖指标。
- 独立评价执行器：读取冻结代码与配置，在独立环境中重跑；产生验证报告。

**已确认**：研发阶段使用本机 OrbStack 的 Docker Engine 和 Docker Compose，不额外创建虚拟机，不引入云集群或消息队列。
研究员、实验执行和验证使用职责分离的容器；并非每个场景必须创建一个容器，一批场景可以属于同一次实验执行。
调度组件管理容器生命周期；研究员不直接获得 Docker 管理接口。证据存储在容器生命周期之外。
后续可迁移到 Linux 主机或云虚拟机；额外虚拟机不是当前的前置依赖。
研究员工作区可写；canonical case、验证代码和正式评价数据由服务端管理。
正式自主运行使用容器或等效 OS 隔离，限制挂载和访问权限。仅目录分隔不能声称实现独立权限。
本机进程模式可用于调试；不能据此验收正式评价隔离。
本机采用原生 `linux/arm64` 作为建议构建目标。跨架构镜像分别记录环境并复核结果；模拟运行与原生运行的性能指标分开报告。
运行可用性、实际隔离和数值工具验证证据见状态文件，不能以部署设计替代运行验收。

开发数值路径采用 MATPOWER 8.1 / Octave 7.3.0 + Python 编排，原生 arm64 参考镜像、case hash 和包清单已记录在 `configs/numerical-environment.json`。执行按固定镜像 ID 重放；APT 构建源尚未固定为历史快照，重建镜像需要新环境记录与重新验收。
若参考路径受阻，可先用明确标记的替代实现调试接口；替代路径不能直接获得参考一致性验收。
初版沿用 AAR 的 Claude SDK，不同时建设多模型供应商框架。

### 4.1 当前可执行切片

本机参考入口为 `python -m powerflow_lab.reference`，具备真实 case118 实验、独立方程/运行约束检查、不可覆盖的试验产物、并发幂等、失败保留与新 trial 重放。操作和证据见 [P1 数值验收](validation/P1-NUMERICAL-LAB.md)。

当前校准 profile 为 `fixed-pv-pq-single-slack/1`：连通网络、单参考节点、恒功率负荷、固定拓扑、不做 Q 限值 PV/PQ 切换；平启动 NR 仅为参考。原输入中固定量保持不变，允许求解所需的 Slack 有功及 PV/Slack 无功变化，仍单独检查其运行限值。缺少支路限额维持未评估。此 profile 是已实现能力，不收窄用户可研究的方法范围；超出当前实现的控制政策须新增适配与验证。

本地 runner 以文件锁及原子 manifest 提供单机证据入口；尚未实现正式控制服务的数据库预算、权限及恢复对账。未知在途执行阻止自动重跑。当前受限容器只运行固定参考脚本，不能据此声称任意候选执行或独立评价隔离已通过验收。

## 5. 研究契约

**已确认**：研究变量有默认值，用户可以自主控制研究边界和方向。求解方法从开始就是研究变量。
固定参考基线不意味着固定候选方法。候选采样器、求解器及其组合都可以由智能体提出、实现和比较。

建议起始课题：以 IEEE-118 为参考，在明确运行规则和预算下，探索更丰富的有效运行样本及更可靠、高效的求解方法。
固定拓扑是起始默认值，用户可以修改。具体已知分布、OOD 参数范围和运行限值需校准后写入实际课题契约。

### 5.2 变量控制模型

每个变量包含：默认值、有效值、控制模式、允许范围、修改权限、生效范围和变更记录。

- `fixed`：在当前契约中固定。智能体可以提出修改建议，不能自行改变。
- `bounded`：允许智能体在显式数值区间或候选集合内修改。
- `open`：允许提出和实现新方法；仍受问题语义、资源预算及执行权限约束。

用户可以修改变量模式和方向。更改产生新的契约版本；正在运行的 trial 保持启动时版本，除非用户明确停止并重新提交。
智能体在已有许可范围内试验无需逐次审批。跨越许可范围应提交有证据支持的建议。
默认值合并用户配置后形成完整、可执行的契约。参数缺失或范围冲突时，执行入口必须报明原因，不得悄悄使用工具默认值。

同一契约用于研究员提示词、执行前检查和结果解释。方法变量可在一次研究中变化，正式比较的评价规则保持版本一致。

下面仅展示配置语义，尚非已实现的配置格式：

```yaml
research_variables:
  network:
    default: ieee118
    mode: fixed
    value: ieee118
  topology:
    default: original
    mode: fixed
    value: original
  sampler:
    default: lhs
    mode: open
    custom_implementation: true
  solver:
    default: newton_raphson
    mode: open
    custom_implementation: true
reference_baseline:
  sampler: lhs
  solver: newton_raphson
  initialization: flat
```

此片段省略运行规则、预算与验证阈值，不能直接作为可执行实验配置。

### 5.2.1 已实现的变量策略子契约

`contracts/variable-policy.schema.json` 与 `asr_service/contracts.py` 实现变量声明、默认值解析、fixed/bounded/open、类型/范围/作用域及修改角色校验。`asr-variable-policy/1` 是完整研究契约的组成部分，不代替 `asr-contract/1`；预算、问题/评价引用和实际执行能力仍须单独验证。示例与本地接口见 [变量策略说明](../contracts/README.md)。

本地 SQLite repository 支持不可覆盖的修订、幂等发布、并发版本检查、显式绑定切换和同事务事件。绑定关联外部运行 ID，不创建研究运行或调度实验；当前仅有受信任进程内接口，actor 参数不是身份认证。正式 trial 受理前必须将绑定、预算和执行权限纳入统一事务。

### 5.3 比较与变更语义

- 修改负荷、出力或拓扑：记录为场景变化，不宣称解决了原来的固定输入。
- 修改初值、算法或数值实现：可作为同一输入上的求解方法比较；独立验证仍回到原问题。
- 修改负荷模型、控制政策或 Q 限值处理：检查是否改变数学问题，必要时形成新的问题定义和独立结果组。
- 求解器内部容差、迭代上限和停止条件允许研究；最终独立验证阈值在同一评价协议内固定。
- 用户可修改评价规则、分布和预算；新规则产生新协议版本，旧结果不得被静默重算或重新解释。

比较采样器时使用相同参考求解协议；比较求解器时使用同一组输入。
采样与求解联合方法通过交叉对照识别贡献，并计入热启动参考解、多次尝试、训练和延续路径的成本。
允许方法输出替代方程或中间状态，但最终有效性必须由原始问题的验证决定。

初值、历史解、训练标签和中间信息的来源及获取成本必须记录。禁止把正式评价数据作为候选方法开发资料。

输出标签分别记录：输入有效性、求解状态、方程验证状态、运行约束状态、OOD 分组。
未知或未找到根不能改写为物理不可行。
未提供运行约束的项目必须标记未评估，不能算作运行可行。

指标分别展示：唯一方程有效样本、唯一运行可行样本、预定义特征分区覆盖、重复率、计算成本。
覆盖指标只是代理指标；完整可行域未知，不报告未经支持的“全可行域覆盖百分比”。
20–50 个固定种子场景用于管线验证。研究比较所需规模根据成本和波动校准。

## 6. 身份、数据与状态

区分三种身份：

- `research_run_id`：一个研究员在一个课题上的持续工作，跨会话恢复时保持不变。
- `trial_id`：一次冻结输入和配置的数值实验，可包含多个 scenario。
- `attempt_id`：同一个 trial 的一次执行尝试；重试分配新 ID，不能覆盖前一次结果。

现有 AAR Experiment 对应研究运行的编排记录。新增数值试验清单关联该记录，不建立第二套研究员调度数据库。详细设计采用本机单控制写入服务扩展上游 SQLite；Supervisor 仅执行受理后的派发意图，Capstone 仅保存投影。该技术选择尚待实施验证。

服务端试验清单保存：契约版本、作者、代码快照 hash、输入 hash、参数、种子、求解器和验证器版本、请求预算、状态事件和产物 hash。
结果保存逐场景终止原因、耗时、迭代、残差、约束违反和日志路径。
采集不到的轨迹明确标记 unavailable，不能伪造迭代数或诊断值。

执行状态：queued → running → succeeded / failed / timed_out / cancelled / interrupted。
succeeded 仅表示执行与产物写入完成，不代表方法有效，也不代表每个场景收敛。

先持久化请求和预算预留，再启动执行。相同幂等键和相同请求返回同一 trial；同一键但不同请求拒绝。
产物在临时目录写入，完成后校验并原子发布 manifest。无终态 manifest 的目录不能作为完成结果读取。
原始产物一经发布不再覆盖。更正和新解释通过关联记录追加。

| `inspect_trial` | trial ID、结果筛选条件 | 状态、指标、诊断摘要与证据路径 |
| `publish_finding` | 结论、范围、支持/反对 trial ID、限制 | 经版本化的 finding；作者只能发布候选或初步结论 |
| `request_replication` | finding ID、冻结策略和配置 | 复核请求 ID；由独立身份执行并记录结论 |

共享发现复用 AAR Forum 和本地同步。论坛是交流入口，证据清单是实验事实来源。
研究笔记记录意图和推理；恢复时以服务端实验状态校正笔记，不能仅相信模型自述。

## 8. 预算、停止与恢复

分别限制研究会话时长、单次数值实验时长、累计求解尝试数和研究模型调用预算。
每次重试、延续路径中间求解和验证调用分别记账；同时报告总耗时和资源环境。
请求前预留预算，结束后结算；并发请求不能超额分配。已消耗预算在失败时不退回。
模型费用若依赖延迟上报，只能作估计；不能宣称精确硬美元上限。记录未结算调用，禁止静默无限重试。

超时由外部监督程序处理活动会话和子进程，不能只在会话之间检查。
连续基础设施错误达到配置上限后退出并报告原因。科学负面结果不等同于基础设施错误。

恢复时核对进程启动标识、心跳和执行记录；不能只用 PID 判定运行状态。
无法确认存活时先关闭受影响入口并对账，无法恢复的 attempt 标记 interrupted，保留部分产物。确认旧执行已退出或被接管前，不释放预留或启动替代进程。显式重试创建新 attempt。
已完成 trial 不因 Agent 重启自动重复执行；预算与证据身份跨会话保留。

## 9. 评价与研究自主性

开发环境允许详细反馈和反复实验。正式评价在策略冻结后使用未参与开发的场景族。
反复反馈给研究员的集合只能称开发/验证集。

采样器提交可运行策略，由评价端在受控预算下执行，不能只提交挑出的成功样本。
候选代码在隔离执行环境运行，不可读取正式标签、评价器凭据或修改评价规则。
评价器重算指标；研究员填写的指标只是声明，不能作为权威数值。

区分两种复核：

- 复现：相同冻结输入与配置，在干净环境重跑；数值采用预先固定容差，运行时间不要求一致。
- 泛化检查：在未参与开发的场景族和种子上执行冻结策略；需单独报告，不能以重跑替代。

算法与验证器不得完全复用同一条未经交叉检查的残差计算路径。
至少用故意扰动的电压、单位/索引错误、输入被改变、越限案例检查验证器是否会错误放行。

研究员自行选择阅读、诊断、实验与实现顺序。系统只约束可执行契约、证据、资源与身份权限。

### 9.1 人类研究者介入机制

**已确认基本设定**：人类可以在任何时刻观察、提问、补充信息或发出控制指令。系统在关键事件提供介入入口；这些事件不是每轮必须通过的人工审批步骤。下述具体协议与界面仍是实现设计，尚未验证。

| 介入节点 | 人类可以做什么 | 建议默认行为 |
|---|---|---|
| 课题启动或重设 | 明确目标、变量模式、资源额度、评价规则、停止条件 | 已授权契约内启动；缺失执行必要条件时只询问缺项 |
| 假设提出与方法选择 | 提供领域知识、文献、反例；推荐、排除或提高某方向优先级 | 异步指导；契约内探索继续 |
| 实验设计与扩大规模 | 检查对照是否公平、补充场景、调整变量范围或预算 | 小实验自主运行；超出授权边界的部分等待决定 |
| 实验运行期间 | 查看状态与日志；停止新提交、取消指定实验、修改后续任务 | 已启动实验保持原契约；改变在明确边界生效 |
| 异常、停滞与证据冲突 | 解释物理现象、纠正假设、决定修复、转向或增加资源 | 一般数值失败自主诊断；预算耗尽或必要权限缺失时暂停受影响工作 |
| 候选发现形成 | 质疑结论、指定反例或消融、请求独立复核 | 主动通知并展示证据；无回复不等于认可 |
| 阶段复盘与成果交付 | 调整方向、选择投入重点、审查科学意义和结论范围 | 按约定事件或周期复盘；对外发布另按用户授权执行 |

交互分为三类，避免自然语言评论被错误执行为控制命令：

- **交流与注释**：提问、解释、领域经验和资料；不自动改变运行契约。人的专业判断记录来源，仍与实验事实区分。
- **研究指导**：优先级、变量范围、预算与方向调整；系统显示解读、目标对象、有效版本和生效点。仅在影响不明确时澄清，不重复确认已清楚授权的操作。
- **运行控制**：暂停提交、取消实验、恢复或结束课题；返回实际执行状态。收到请求不等于已经停止进程。

建议默认采用异步指导与事件通知。用户可为指定课题设置更强的审阅节点；不要求每次提出假设或修改代码都等待人。
同一个请求可能仅阻塞一个实验或一个方向，其他已授权且不依赖该决定的工作可以继续。等待回复期间不能自动提高权限或预算。

介入事件记录：作者、时间、指向的课题/研究运行/实验/发现、原始内容、系统解读、契约版本、执行状态和生效点。
已过时的回复必须核对目标版本；无法安全适用时重新澄清，不能直接覆盖新决定。
人提出的新问题和资料可关联现有实验，研究员应说明采纳、待验证或未采纳的理由及证据。

修改规则：

- 新范围或新评价协议生成新契约版本，作用于后续实验；旧实验结果保留原条件。
- 默认“暂停研究”停止提交新实验并暂缓排队实验派发，允许在途实验完成并保存证据。明确“立即停止”则取消目标进程并保留部分产物；这两个动作在界面中分别显示。
- 取消与完成并发时，以持久化执行事实为准；不能删除已完成结果或误报取消成功。
- 恢复从实际实验状态和剩余预算开始，不依赖研究员对上次会话的文字记忆。
- 不依赖手工编辑服务器文件或重启整个系统完成正常干预。

建议首版入口：课题对话、变量/预算配置、实验列表及日志、发现与复核视图。
人类工作台采用 Capstone 的专属科学研究模式（§9.2）；AAR Forum 和 Dashboard 保留为已有研究协作与调试能力，避免同时建设两套面向人的控制中心。需要补齐控制指令、权限、生效点和回执；聊天消息本身不等于控制接口。
通知频率、停滞判据、具体审阅节点和 UI 形式仍待确认，不预设为已实现能力。

Capstone 架构文档将其问题驱动的 enterprise research mode 标为已接受设计、非已实现发布；部分研究机制已有代码。不能把这些名称直接等同于本项目所需的自主科学实验闭环。

已确认职责划分（具体接口为实现设计）：

- **Capstone 科学研究模式**：课题对话、材料、变量与预算编辑、方向指导、运行观察、发现质询和复核入口。它可解释与整理证据，但不能自行宣布数值验证通过。
- **科研控制适配与运行服务**：接收版本化契约、指导和控制请求；管理运行身份、权限、预算与回执；将研究与实验状态投影给工作台。可以先作为本项目服务内模块，无需新增独立部署单元。
- **AAR 执行器**：读取有效契约和指导，提出假设、修改候选代码、发起实验、解释结果与共享发现。一个运行的研究循环由一个执行器负责，避免 Capstone 与 AAR 各自维护相互竞争的实验计划。
- **实验服务及独立评价器**：拥有实际执行、原始证据和正式验证结果。Capstone 中的展示副本与研究员的文字总结均不能覆盖这些事实。

专业 Domain Pack 对外提供明确的研究动作，例如提交课题、读取运行、追加指导、暂停提交、取消实验与请求复核。AAR 编写和运行候选算法的自由度保留在隔离研究工作区和受控执行环境中；不需要给 Capstone 的专业领域会话开放任意宿主机执行权限。现有 pandapower 能力可在契约允许时成为研究工具，不能直接替代本项目尚待建立的 MATPOWER 参考与独立验证协议。

必须明确的接入语义：

1. 课题可关联多次运行、多段对话；一次运行包含多个 trial 和 attempt。使用显式映射，不把 Capstone turn/attempt 与本项目运行或实验身份直接等同。
2. 长期研究在工作台断线或一轮对话结束后继续；用户仍可提问、发送指导和控制，无需等自主研究结束。
3. 控制请求带幂等键、目标与预期版本。界面区分已接收、待生效、已执行、拒绝；只有执行端确认才能显示已暂停或已取消。
4. 指导作用于明确边界，修改契约生成新版本；既有实验保留原版本，比较时显式处理条件差异。
5. Capstone 展示可恢复的状态投影和事件；运行、预算、实验与正式复核各有唯一写入责任方，不双写两个权威账本。

首个适配切片建议：创建课题并配置研究变量 → 启动一个 AAR 研究运行 → 运行中追加指导/暂停新提交 → 查看真实 trial 与候选发现 → 请求独立重跑并查看回执。刷新或断开工作台不会丢失运行；重复控制请求不会重复执行；指导是否采纳有记录。

完整可视化假设图、多研究员协作和复杂报告编辑可后续增加。P1 的真实数值环境仍是底层前提；工作台适配不要求先完成整个 Capstone 企业研究功能。

## 10. 首个端到端验收

1. 固定一个小型真实 IEEE-118 基线并验证原方程残差。
2. 单研究员读取基线，提出一个可检验的问题并运行诊断实验。
3. 实验服务保存完整证据；研究员提交带证据引用的 finding。
4. 在执行途中及结果发布后分别注入中断；验证状态恢复、幂等性和预算保留。
5. 独立执行器从代码快照和 manifest 重跑，生成一致或不一致的明确报告。
6. 研究员读取复核结果，决定继续、修改假设或记录负面结论。

系统验收可以由可信的负面结果通过。科学成果验收需额外满足同预算对照和独立场景证据。
没有真实模型调用，仅使用脚本模拟研究员，最多证明工程链路，不能宣称自主科研通过。
没有真实潮流计算，仅使用假求解器，最多证明接口与恢复机制，不能宣称电网实验通过。

## 11. 实施顺序

- P0：设计与源码映射。完成当前文档和工作清单对齐。
- P1：可重放的真实领域实验。固定上游来源与数值环境，建立 trial 证据、验证和幂等执行。
- P2：单研究员闭环。适配 AAR 提示词和工具、共享发现、外部停止与恢复。
- P3：独立复核与系统验收。验证隔离、故障恢复和重放；形成第一段可信研究轨迹。
- P4：首份科学成果。冻结比较协议，运行样本生成、求解方法或联合研究及独立评价，交付数据、方法与局限。

每个阶段有可运行验收；不按任务书算法清单机械推进。

### P2 local budget primitive (2026-11-02)

本地预算原语 `asr_service/budgets.py` 已实现项目级整数计量、事务预留、幂等结算及超额记账。执行退出由可信调用方声明，尚未连接进程核验、运行子额度、完整准入或 AAR；不能作为执行授权。

预算原语新增 `reserve_many` 与 `reserve_many_in_transaction`：多维额度原子预留、完整请求重放校验，可加入拥有者事务；尚未实现完整 trial 准入。事务调用方必须使用同一数据库，并负责 trial/事件/派发意图及认证。

本地 `asr_service/references.py` 提供按项目和类型隔离的不可变 JSON 元数据引用，读取时复核内容 hash，并支持在拥有者事务中查询。注册是可信内部操作，不验证外部产物可用性、科学协议完整性或身份权限；完整 trial 准入仍未实现。

`asr_service/admission.py` 已提供本地准入准备事务：核对显式 policy ID/revision 和项目引用，原子保存 trial/attempt 身份、预算束和事件；重复请求复用身份。必填可信 owner_gate 承担认证、外部运行门控、完整契约和产物/能力检查，当前没有真实适配。queued 记录仅为准备意图，无领取/派发/租约；不得用于真实执行授权。

本地准入准备接口将必填 `authorize` 与 `owner_gate` 分开：每次请求先校验访问权限；已受理的相同请求直接返回原回执，新请求才检查运行门控。暂停后恢复丢失响应不会创建新试验或再次预留预算。两种回调仍需真实服务适配。
