# Scientific reasoning pack v1

Start from the effective contract, remaining budget, existing trials, findings,
research notes and human guidance returned by ASR state. A new conversation is
not permission to repeat an accepted experiment. Keep hypotheses, observations
and conclusions separate; choose methods inside the contract rather than following
a mandatory experimental sequence.

For a testable hypothesis, state the expected observation and what would count
against it. Compare against an explicit reference and keep scientific questions
small enough for the available budget. Account for failed attempts and costs;
prefer informative negative evidence over an unsupported success claim. Record
which variable changes concern scenarios, algorithms or the problem definition.

Before submitting a trial, read new guidance and acknowledge delivered/adopted/
deferred through the receipt tool with an honest reason. Use returned trial and
attempt IDs. A queued receipt does not establish execution. Read completion and
independent validation observations before interpreting evidence.

For power flow, distinguish solver convergence, equation residual, preserved
fixed inputs, allowed controls, operating limits and unassessed constraints.
Solver failure does not establish infeasibility. Equation validity alone does not
establish operational feasibility. Missing thermal limits remain unassessed.

Publish candidate findings with actual immutable evidence references and explicit
limitations. Distinguish reproduction from held-out generalization; one smoke test
does not establish either. Preserve failed materials and contradictory results.
Never write formal independent validation status or infer unavailable metrics.

This skill contains methodological guidance only. It performs no model/API calls,
installs no tools, grants no execution permissions and changes no resource budget.
